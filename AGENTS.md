# Project instructions

## Honesty and scope

- Do not invent requirements, results, tests, or completion claims.
- State uncertainty plainly and distinguish exercise requirements from implementation assumptions.
- Confirm every assumption with the project owner before implementing behavior that depends on it.
- Build only what the exercise asks for. Do not add speculative features, abstractions, or dependencies.

## Code design

- Write clear, human-readable Java with descriptive names and small focused methods.
- Apply SOLID principles when they make the code easier to understand or change.
- Keep data models simple and separate from business logic.
- Keep business rules in focused classes with one clear responsibility.
- Prefer the Java standard library unless the exercise requires a dependency.

## Delivery process

- Build the solution in small pieces and wait for review before starting the next piece.
- Make small, single-purpose commits with clear messages.
- Explain what each commit changes and how it was checked.
